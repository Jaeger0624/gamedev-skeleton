# 阶段 3：攻击性检查

> 注入原子：skills/extreme-extrapolation（极端化推演：数值/条件拉满会怎样）+ pattern-recognition（找"非预期解"）

## 线 A：第 4 章「时缝之间」

### 传送门极端化推演

**最优情况**：玩家在关卡 1 就理解传送门方向映射，后续关卡全部秒解。
→ 风险：教学坡度过平，"顿悟"变"套路"。修正：关卡 2 的出口角度映射应有一个**反直觉案例**（如入口速度向下，出口速度向左，需旋转装置配合）。

**最坏情况**：玩家不理解"相对角映射"，把传送门当随机门用。
→ 风险：挫败感累积。修正：关卡 1 的配对门必须**正对着入口**（角度映射为恒等），让玩家先建立"进哪出哪"的直觉，再引入角度变化。

**与最强现有装置组合**：传送门 + 可移动可旋转炮台（Ch2 已引入）= 玩家可以把炮台的弹道折叠到任何位置。
→ 碾压风险：炮台本身已是"自由度最高"的起点，加传送门后可能"一关一解"变"一关万解"，削弱设计意图。修正：Ch4 前半的炮台必须固定角度，只允许传送门端点可移动。

### 回溯极端化推演

**最优情况**：玩家用回溯精确控制每次多次节点的触发时机。
→ 可接受，这是设计意图。

**最坏情况**：玩家不理解"回溯只重置位置不重置装置角度"，以为回溯是"撤销"。
→ 风险：操作困惑。修正：关卡 6 必须有一个"回溯后装置角度保留"的明确反馈（如回溯后弹板角度与回溯前不同，导致轨迹差异）。

**组合碾压**：回溯 + 多次节点 + 时序门 = 玩家可以用回溯"偷"时间窗口。
→ 可接受，这是"时间换次数"的设计意图。但需限制：单次运行最多回溯一次（已在项目文档中确认）。

### 非预期解扫描

- 传送门是否可以让花生"卡"在门里？（物理引擎边界情况）
- 回溯是否可以让花生"卡"在回溯前的位置？（如回溯前花生在反花生区域内）
- 传送门 + 反重力区域 = 花生在门内时重力方向是否重置？（需要工程验证）

## 线 B：全新章节「相对性」

### 重力旋转极端化推演

**最优情况**：玩家在关卡 1 就理解"旋转改变世界"，后续关卡全部秒解。
→ 风险：同线 A，教学坡度过平。修正：关卡 2 的弹板必须在 0° 和 180° 下有**完全不同的功能**（0° 是地板，180° 是天花板），迫使玩家重新思考。

**最坏情况**：玩家不理解"旋转是全局的"，以为可以局部旋转某个装置。
→ 风险：操作困惑。修正：布置阶段的旋转 UI 必须是"整个世界旋转"的视觉反馈（如整个关卡背景倾斜），不是单个装置旋转。

**组合碾压**：重力旋转 + 传送门 = 玩家可以折叠+旋转空间。
→ 碾压风险：传送门本身已是空间折叠，加重力旋转后可能"一关一解"变"一关零解"（过于复杂）。修正：Ch5 的传送门必须固定配对，只允许重力方向可变。

**组合碾压**：重力旋转 + 回溯 = 玩家可以"回到过去再旋转"。
→ 碾压风险：时间+空间双重操纵可能过于复杂。修正：Ch5 不引入回溯，回溯是 Ch4 的机制，Ch5 只引入旋转。

### 非预期解扫描

- 重力旋转是否可以让花生"飞"出边界？（需要边界碰撞检测）
- 45° 重力下，弹板的反射角度是否仍然可预测？（需要物理引擎验证）
- 旋转后，节点的"顺序"是否仍然有意义？（如节点 1 在 0° 时在上方，90° 时在左方）

## 修正汇总

| 问题 | 修正 |
|---|---|
| 传送门角度映射反直觉 | 关卡 1 配对门正对入口，关卡 2 引入反直觉角度 |
| 回溯后装置状态困惑 | 关卡 6 明确反馈"装置角度保留" |
| 炮台+传送门一关万解 | Ch4 前半炮台固定角度 |
| 旋转+传送门过于复杂 | Ch5 传送门固定配对 |
| 旋转+回溯过于复杂 | Ch5 不引入回溯 |
