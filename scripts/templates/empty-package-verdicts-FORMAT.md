# 判据库格式

> 判据 = 判断标准，不是知识陈述。知识告诉你"世界上有这么回事"，判据告诉你"此刻这个岔路口该往哪走"。

## 判据条目格式

```markdown
# [判据名称]

**内容**：一句话可执行的判断标准。
**依据**：从什么推导而来（理论/案例/复盘），须可质疑。
**适用**：品类 tag + 场景。
**反面**：什么情况该判据会带偏。
**来源**：（可选但推荐：type: 视频|书籍|文章|讲座|论文|项目复盘|理论推导 / ref: 标题+作者+链接 / 提取日期 / 原观点编号；外部输入沉淀必填）
**有效性记录**：使用日期 / 项目 / 结果 +1 0 -1 / 备注
```

> **转正通道（2026-08-23 双通道分流）**：判据 = 候选 → 可质疑性审查 + ≥1 次 run 挂靠记录 + 用户确认 → 正式；用户确认记入有效性记录（`用户确认 / <日期> / 认可 / 来源类型`）。技能原子仍走 3 次真实 run 验证（见 `atoms/GOVERNANCE.md`）；骨架条目/观点走用户确认制。

> **判据↔动作分工（2026-08-24 标准化，见 GOVERNANCE）**：判据=标准句（应当/该不该）；可挂**一句**设计动作（操作化备注），但不得写成"执行 N 步"手册体（手册体=原子，走原子通道）；判据侧默认动作不占原子通道，动作成为独立原子时判据侧只留交叉引用。
