# AI 工作流

> 本文只规定协作与交付流程。文档职责见 [`README.md`](README.md)，项目内容以对应事实源为准。

## 开始任务

0. 按 `HARNESS-PROTOCOL.md` §0.0 执行启动铁律（协议 → FRAMEWORK-MIND 完整段 → 状态恢复）。
1. 读取 `项目进度.md`，确认当前工作焦点和未完成事项。
2. 按任务类型读取唯一事实源：
   - 玩法规则：`玩法设计/玩法设计总览.md`；
   - 叙事与文本：`世界观与故事/世界观与故事总览.md`；
   - 视觉与音频：`美术表现/视听方向.md`；
   - 具体功能：`技术文档/` 或 `玩法设计/设计/` 中对应方案；
   - 设计判断标准：全局骨架 `C:/Users/32337/.gamedev-harness/verdicts/`（只引用，不复制）。
3. 开发前遵循项目 `AGENTS.md`（Maker 托管：引擎/MCP 协议）与 `HARNESS-PROTOCOL.md`（设计流程协议）。
4. 先核对现有代码和数据，再确定改动边界与验收标准。

## 实施原则

- 用户代码放 `scripts/`，资源放 `assets/`；不修改引擎知识目录与只读库。
- 数据、规则、运行时表现和编辑器视图分离；UI 回调发送语义命令，不直接复制业务逻辑。
- 优先完成可验证的最小闭环，不提前实现未确认范围。
- 物理与碰撞功能先明确长度单位、碰撞区域、检测目的和边界情况。
- （项目级原则随生长补充；通用设计判断标准 → 全局骨架，不在此重复。）

## 检查与收尾

- 关键设计决策/测试结果按 `dev-log/DECISION-LOG.md` 格式追加（依据判据 slug + 结论）。
- 定稿方案提升到对应专项目录（`技术文档/` 或 `玩法设计/设计/`）；runs/ 留过程。
- Maker 构建/预览/提交走托管 `AGENTS.md` 的引擎协议（不再另写）。
