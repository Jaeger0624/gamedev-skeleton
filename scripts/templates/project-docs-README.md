## 专项与历史

| 目录 | 职责 |
| --- | --- |
| `技术文档/` | 一个系统或功能的需求、设计与实施方案；允许完整论证，但不复制全局进度 |
| `玩法设计/设计/` | 玩法讨论、方案比较和决策依据；总览只接收最终有效结论 |
| `美术表现/` | 视觉规范、构图方案、验收规范和资源登记 |
| `正式关卡/` | 正式内容配置（当前生效的关卡/事件数据） |
| `版本归档/` | 已结束次版本的完整变更记录；只读历史，不作为当前事实源 |
| `开发者上传文档/` | 用户提供的原始资料；保留原貌，不作为当前结论自动生效 |

## 信息归属规则

- "现在正在做什么"只写 `项目进度.md`。
- "某版本已经做完什么"只写 `版本归档/` 下的版本记录；次版本结束后从草稿区归档。
- "当前玩法/视听/叙事究竟是什么"分别写三个总览。
- "功能为什么这样设计、准备怎么实现"写对应专项设计文档（`技术文档/` 或 `玩法设计/设计/`）。
- 其他文档需要这些信息时只写一句结论并链接事实源，不复制段落。
