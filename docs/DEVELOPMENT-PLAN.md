# 框架升级开发计划（多阶段）

> **定位**：2026-08-24 框架升级 run 的执行计划。依据 = 待办重排（A/B/C 档）+ 近几轮讨论定案：
> ①流程动沉淀→模板动作链→新项目继承（防"换新项目靠碰"）；②三实体职责+使用时刻表（理解=骨架/判断=判据/动作=原子）；
> ③PACK=内容层生长物、编排=建议非权威；④目标形态=自动运作（机器做机械层、你只做设计裁决+圈选升级）；
> ⑤红线：不膨胀不冗余（面板=甜品不做；已有机制不搬）；红线 7（观察先确认再普适化）；状态在文件（每阶段落盘+提交）。
> **原则**：先做继承链断点（A 档）→ 再做制度壳（B 档）→ 其余全部"按需长出"，禁止批量预做。

## 阶段 0 · 基线核实（前置，半天内）

- **目的**：不开盲工——调查决定阶段 1/2 的实现方案。
- **内容**：
  1. DSH 第二协议注入机制调查（workspace 指令是否支持多协议文件 / HARNESS-PROTOCOL 自动注入可行性）→ 决定 M3' 分支 A（自动注入）或分支 B（preset 契约化）；
  2. writer.ts 协议模板现状核对（已含条款清单 vs 需补：§3.7-3.10 / 交流规范 / 内容生命周期分层 / 切片纪律）；
  3. 插件 build/装配链路确认（dev_build_plugin → 热载/装配验证要点）。
- **产出**：`docs/DEVELOPMENT-PLAN.md` 更新（方案定稿）；结论入 PROGRESS。
- **验收**：两个分支点有事实依据，无猜测。

## 阶段 1 · M1′ 动作链模板化（继承链核心，2-4h）

- **目标**：本次 run 已沉淀并获用户确认的动作链，全部进入新项目继承链（今天接新项目即完整版）。
- **内容**：
  a. 插件 `writer.ts` 协议模板同步：§3.7 挂载前验真 / §3.8 骨架留痕 / §3.9 决策时挂载 / **§3.10 原子执行记录**；
  b. 协议模板补：**交流规范条款**（同事式/选择题+自定义/切片反馈/"已记录"确认——默认条款，项目可覆盖）+ **内容生命周期分层**（run=簿记 / 脑暴方案=候选 / 转正提升设计域 / 决策=叙事链）；
  c. **切片写作纪律**（因果自洽先于结构）升为流水线通用底线（card-batch-design / `_FORMAT` 注明）；
  d. 星尘叙事者现有协议人工对齐（或标注"下一项目验证"）。
- **产出**：新项目接入生成协议 = 完整模板；正负测试（生成产物含全部条款、无旧模板残留）。
- **验收**：mock 生成一份协议 → 条款清单逐项勾销；插件 build + 装配验证通过。

## 阶段 2 · M3′ 会话启动链（继承链第一环，≤半天决策 + 1-2h 实施）

- **目标**：新会话"进得来、记得读协议"——不靠用户记得选预设。
- **分支 A**（DSH 支持多协议注入）：接入配置/插件实现 → 协议自动进会话。
- **分支 B**（不支持）：preset 契约化——`START-HERE`/README 明示"项目会话=Harness 项目预设"；可行时 preset 排序提前；启动自检报告（三实体自检+恢复状态）已内建，确认链路。
- **验收**：新开项目会话，未经用户提示即完成协议→心智→恢复→自检（模拟或用户首次实测）。

## 阶段 3 · 流程生长轨（动态沉淀的制度壳，1-2h 文档）

- **目标**：让"流程在 run 中诞生→圈选→模板化"成为默认习惯，升级裁决有固定接口。
- **内容**：
  a. 协议/流水线加「**流程观察**」段（摩擦/失败/被纠正/有效模式，当场一行，不加工不普适化——仿 00-brief 复盘素材段）；
  b. run 结束圈选流程（随 05-review：观察清单化 → 用户逐条 沉淀/弃/改）；
  c. **沉淀验收三问**：落哪条模板动作链？新项目继承链哪一环？答不出=沉淀未完成；
  d. 星尘叙事者本次 9 项沉淀清单回填为首案例（证明机制 + 首样本）。
- **产出**：协议 §3.11（流程观察与圈选）+ 流水线回顾段说明；首案例回填。
- **验收**：下个 run 产出含流程观察段；圈选走通一次。

## 阶段 4 · M4 观测联动（随 A-01 接续 run，机制先就位）

- **目标**：05-review 从 §3.10 执行记录**聚合**原子使用表（禁回忆回填）→ 3 验计数路径通。
- **内容**：流水线回顾段注明数据来源（执行记录→观测表）；候选 3 验计数规则标注（机制文档层）。
- **依赖**：A-01 接续（用户暂停中）；**工具化延到 run 实际跑起来再定型**（不预先做）。
- **验收**：星尘叙事者续跑阶段 3 时，05-review 有执行记录来源可对账。

## 阶段 5 · 按需长出（无排期，逐项随需求）

- 挂载验真工具定型（run 用到时）；C-03 注入补全（用户画像/共识 top3）；C-06/F-03 检索小改；
  PACK 定位注记（`_TEMPLATE` 补"编排=建议非权威、内容层生长物"）。
- **原则**：每项都等真实 run 长出需求或用户点名——**禁止批量预做**。
- 验收：逐项按需。

## 明确不做（防膨胀防线）

- 面板任何"操作台/观看"功能（甜品判定，AGENTS §6）；
- 落库机检搬进插件（G-20 脚本已做且验证，搬=冗余）；
- checkpoint 产出格式校验（需求未长）；
- 向量轨 C-01（mnemon 宿主故障 + 无活跃需求，双条件挂起）；
- C-04 设计型双维、任何"先设计等 run 验证"的规范。

## 执行方式

- 每阶段完成：落盘（PROGRESS/文档）+ 双仓提交（框架仓 push / $HARNESS 本地；项目仓按惯例）；
- 阶段间衔接：A 档（1-2）优先级最高——它们直接兑现"换新项目自动继承"与"零操作会话"；3 之后随真实 run 节奏推进；
- 串行不并行：本计划全程一个工作区（框架核心区）执行，项目 run 不受干扰。
