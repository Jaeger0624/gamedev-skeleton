## 三、方案提取（P1-P7；三问附于各条）

### P1 · 注入链修复：判据契约校验 + 解析器白名单（O1）
- **做法**：①`run_start` 注入 verdicts 前逐个校验 `verdicts/<slug>.md` 存在性——不存在的剔除+注入包标注「判据库校验：剔除 N 条（slug）」（把 PACK 注记自己要求的"挂载前必须验证"变成机制）；②解析器限定「适用判据清单」小节（按小节边界收集，忽略 ⚠️/注记行）；③补收集全局判据清单行（当前整行未收集——顺带修复）。
- **三问**：①落哪条模板动作链？→ 注入链（runStart 装配，机制层）；②新项目继承链哪一环？→ 所有新 run 自动生效；③答得出→ 是。
- **成本**：插件改动（pipeline.ts + reader 复用）+ 构建；**强制建议**（不是可选——本次 run 已因此污染注入包两次）。

### P2′ · PACK 编排=计划牌（架构回审修正；原 P2「全量并入注入包」作废）
- **架构回审**：P2 原案把 PACK 编排全量并入注入包——**用原子重犯阶段 1 已修的骨架全量注入病**（上下文过载+语言榜样）；且架空原子池/发散池/观测信号（全量=选择消失=探索机制失效=§3.10「编排（计划）vs 执行（事实）」失去参照系）。用户质询成立，作废。
- **PACK 角色定位（修正）**：PACK=**品类装配地图（三列）**——理解列（六张力，引用骨架不搬运，[pack] 裁剪优先兑现）、判断列（适用判据清单+**级别标注**：正式/〔候选〕）、动作列（编排偏好表=**计划牌**）。三层分工：原子池=库（库存/演化/3 验计数/亲和度）→ PACK=品类取用规则（地图+目录，非正文）→ 注入包=当次起点（裁剪装备）。
- **做法**：①core 原子按阶段映射注入（[pack] 标注；"必定注入"=装备层必走项，带了≠用了，观测不受影响）；②发散池**只列目录行**（"可按需抽 x/y"），不注正文——选择权留 agent；③判据完整清单+级别显式（〔候选〕）+ 存在性校验（并入 P1）；④`packs/_TEMPLATE.md` 补契约注记（编排表=计划牌；装备语义如上；§3.10 区分）。
- **三问**：①模板动作链=runStart 装配+模板契约注记；②继承链=新 run 全自动；③是。
- **成本**：插件改动（与 P1 同一次）+ 模板注记。
